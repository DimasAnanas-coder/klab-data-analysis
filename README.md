# Запуск проекта

Требуются Python 3.12 или новее, `uv` и Docker Desktop. Команды ниже приведены для PowerShell.

1. Установить зависимости и создать виртуальное окружение:

   ```powershell
   uv sync
   ```

2. Создать `.env` из шаблона:

   ```powershell
   Copy-Item .env.example .env
   ```

   В `.env` можно изменить имя базы, пользователя и пароль. `DATABASE_URL` формируется из этих значений. При подключении настройки загружаются через `python-dotenv`; переменная `DATABASE_URL`, заданная в PowerShell, имеет приоритет.

3. Запустить PostgreSQL в Docker:

   ```powershell
   docker compose up -d
   ```

   Дождись статуса `healthy`:

   ```powershell
   docker compose ps
   ```

4. Создать таблицы и индексы:

   ```powershell
   uv run klab-data-init
   ```

   Команда подключается к базе из `DATABASE_URL` и может запускаться повторно.

5. Импортировать данные из `data/`:

   ```powershell
   uv run klab-data-import
   ```

Запусти консольное приложение командой:

```powershell
uv run klab-data-analysis
```

В меню можно найти версию продукта без известных уязвимостей или показать уязвимости для указанной версии. Название продукта вводится точно как в фиде. Если такое название есть у нескольких производителей, приложение предложит выбрать нужного.

Остановить PostgreSQL можно командой `docker compose down`. Данные сохраняются в Docker volume и останутся после остановки контейнера. Чтобы удалить контейнер вместе с данными базы, выполни `docker compose down -v`.

# Модель данных

В базе данных три таблицы:

- **`products`** — каталог продуктов. `vendor` хранит производителя, `name` — название продукта. Пара `(vendor, name)` уникальна.
- **`product_versions`** — версии продуктов из `versions.json`. Каждая запись связана с продуктом через `product_id`. Одна и та же версия не может повторяться у одного продукта.
- **`vulnerabilities`** — записи об уязвимостях из `vulnerabilities.json`: KLA ID, описание, дата публикации, первая уязвимая и первая исправленная версии. Запись связана с продуктом через `product_id`.

Связи между таблицами — «один ко многим»: у одного продукта может быть много версий и много записей об уязвимостях. Каждая версия и каждая запись об уязвимости относится ровно к одному продукту.

Внешние ключи `product_id` ссылаются на `products.id`. При удалении продукта PostgreSQL удаляет его связанные версии и уязвимости.
